## Outcome

T021 is accepted. The API now exposes a Google-only, dependency-injected Authorization Code + PKCE boundary. Login creates random state, nonce, and verifier values; the transient state is sealed with AES-256-GCM using an injected key and is never logged or persisted. Callback processing applies code/state bounds before decryption, requires an exact state and nonce match, validates Google's issuer, audience, subject, email verification, and redirect, then persists only a SHA-256 session hash. `/me` rotates the session atomically; logout revokes by hash. GitHub/X remain explicitly unsupported.

The real `openid-client` composition is isolated in `createOpenIdGoogleOidcAdapter`. It pins the Google issuer and authorization endpoint and requires a client secret. Tests inject a fake adapter and in-memory store; no test contacts Google or any target.

Secure deployments use host-only `__Secure-*` cookies with `HttpOnly`, `Secure`, `SameSite=Lax`, and `Path=/api/v1/auth`. Development may opt into non-secure names only when the API environment is explicitly `development` and `allowInsecureCookies` is true. Session cookie values are restricted to the canonical 43-character base64url token before hashing.
