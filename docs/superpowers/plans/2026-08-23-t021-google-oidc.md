# T021 Google OIDC Authentication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Google-only, fakeable OAuth Authorization Code + PKCE boundary with encrypted transient state, secure opaque sessions, and API routes that never persist or expose provider secrets.

**Architecture:** `apps/api/src/auth.ts` owns pure claim validation, PKCE state/cookie handling, and an injected OIDC adapter plus session store. `createApp` receives optional auth dependencies and mounts `/api/v1/auth/login`, `/callback`, `/logout`, and `/me`; tests inject a fake adapter/store and an in-memory key. The adapter never performs network I/O in tests, and persistence receives only SHA-256 session hashes.

**Tech Stack:** TypeScript strict, Hono, Web Crypto, Vitest, existing `@touchmyapi/secrets` AEAD primitives where suitable.
